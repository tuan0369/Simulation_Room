\section{Evidence protocol}
The figures were captured from the current Project~2 source during a local run on 14 August 2026. They are state evidence, not a substitute for a machine-readable experiment log. The stress state was created using validated individual room/AHU MQTT commands because the dashboard's guided scenario button publishes \code{twin/ecosystem/cmd/scenario}, to which the simulator does not subscribe. The dashboard also waits for scenario/result topics the simulator never publishes. Therefore, no claim is made that the button caused the captured state.

For a repeatable submission experiment, occupancy randomness should be seeded or disabled, $\Delta t$, initial state, command sequence, duration, artifact/model hashes, and raw MQTT decisions should be recorded. The expected invariants are $0\le g_i\le r_i$, $\sum g_i\le F^{avail}$, and deterministic priorities from the same snapshot.

\section{Automated verification}
The recorded project run reports 75 tests passing, covering AHU physics, coordination, ecosystem command routing, fan-health inference, synthetic reproducibility, legacy room physics/PID, MQTT payloads, and presentation helpers. The README's 54-test statement is stale. The run lacks an archived JUnit/coverage file tied to a commit; this report consequently treats 75 as recorded test evidence, not a signed release certificate.

Gaps include browser-level Project~2 tests, guided-scenario end-to-end tests, real-broker integration, broker-loss recovery, calibration/OOD/model-corruption tests, production authentication/TLS/ACL tests, and proof that risk changes an autonomous action. The latter absence is expected because model action is intentionally advisory.
